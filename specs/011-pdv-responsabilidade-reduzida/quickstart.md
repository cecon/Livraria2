# Quickstart: Validacao do Estoque Oficial

## Prerequisites

- Ambiente Supabase equivalente a producao com migrations ate `0010_turno.sql`.
- Backup/snapshot da base antes de aplicar `0011_estoque_oficial_venda.sql`.
- Credenciais ficam no Notion, nunca no repo.
- PDV e Escritorio configurados com usuarios autenticados, sem `service_role`.

## Local Supabase Docker

Ambiente local criado em `apps/nuvem/supabase` com Supabase CLI via `npx`.
Portas locais:

- Studio: `http://127.0.0.1:54323`
- API: `http://127.0.0.1:54321`
- Postgres: `postgresql://postgres:postgres@127.0.0.1:54322/postgres`

Comandos usados em 2026-07-28:

```powershell
npx supabase@2.110.0 start --workdir apps\nuvem

$files = Get-ChildItem apps\nuvem\migrations\*.sql | Sort-Object Name
foreach ($f in $files) {
  Get-Content -LiteralPath $f.FullName -Raw -Encoding UTF8 |
    docker exec -i supabase_db_nuvem psql -U postgres -d postgres -v ON_ERROR_STOP=1
}

Get-Content -LiteralPath apps\nuvem\migrations\0011_estoque_oficial_venda.sql -Raw -Encoding UTF8 |
  docker exec -i supabase_db_nuvem psql -U postgres -d postgres -v ON_ERROR_STOP=1

Get-Content -LiteralPath apps\nuvem\tests\0011_estoque_oficial_venda.sql -Encoding UTF8 |
  Where-Object { $_ -notmatch '^\\i ' } |
  docker exec -i supabase_db_nuvem psql -U postgres -d postgres -v ON_ERROR_STOP=1
```

Resultado: migrations `0001` a `0011` aplicadas; reaplicacao da `0011`
passou com notices esperados de idempotencia; fixture completo passou com
`ROLLBACK` final.

## 1. Apply Migration

1. Apply `apps/nuvem/migrations/0011_estoque_oficial_venda.sql`.
2. Reapply the same migration.
3. Confirm no duplicate columns, triggers, functions, indexes or baseline rows were created.

Expected:

- Migration is idempotent.
- `saldo_partida_producao` captures the current production saldo once.
- Existing product saldo remains unchanged immediately after activation.

## 2. Venda Pronta Baixa Estoque

1. Pick a known/published product with saldo `S`.
2. Create a sale with one item quantity `Q`.
3. Mark the sale as complete/ready.
4. Read official saldo.

Expected:

- One `saida_venda` movement exists for the item.
- New saldo is `S - Q`.
- Reprocessing the sale does not create another movement.

## 3. Saldo Insuficiente

1. Pick a known/published product with saldo `S`.
2. Create a ready sale with quantity `Q > S`.
3. Read official saldo and divergences.

Expected:

- Movement quantity is `-Q`.
- Official saldo may be negative.
- A `saldo_negativo` divergence is open for admin review.

## 4. Cancelamento Estorna Movimento Original

1. Use a sale already incorporated into official stock.
2. Mark it as canceled.
3. Re-send or reprocess the same cancellation.

Expected:

- One `estorno_venda` exists for each original `saida_venda`.
- Estorno quantity equals the absolute original movement quantity.
- Repeated cancellation does not duplicate estorno.

## 5. Venda Parcial Nao Baixa

1. Create sale header and no items, or create items before marking sale ready.
2. Read movements.

Expected:

- No official movement exists before the ready marker.

## 6. Escritorio Nao Grava Movimento Manual

1. Complete a sale through the Escritorio checkout.
2. Inspect client writes/logs or test mocks.

Expected:

- Client writes sale data and ready marker.
- Client does not insert `movimento_estoque` for `saida_venda`.
- Official movement is generated by cloud automation.

## 7. PDV Saldo Local Simples

1. Sync product with `saldo_publicado = 10`.
2. Sell 2 locally without sync.
3. Cancel 1 locally without sync.

Expected:

- PDV displays `saldo_local = 10 - 2 + 1 = 9`.
- Display labels saldo as operational/simple, not official/accounting.
